{# Shared theme head for the app / admin / onboarding shells (marketing pages stay light-only and do NOT include this — templates/base.html carries the same Counting House palette in its own inline config). Flight Deck (2026-08-31, supersedes Counting House): graphite ink on a cool near-white ground, hairline borders, ONE electric cobalt accent. Display face Space Grotesk on headings; Inter stays the body face. Chrome stays flat; frosted glass is reserved for the Today deck's floating cards. NO tnum anywhere (not even the tabular-nums utility): both faces give the full stop and hyphen figure-width forms under tnum, which mangles amounts and dates — Inter's default figures are already uniform enough, and right-aligned columns do the rest. How it works — no per-template dark: variants anywhere: 1. A pre-paint script reads localStorage 'blam8-theme' (light | dark) and stamps data-theme on before first paint (no flash). There WAS a third choice, 'system', dropped 2026-09-01 (Kris: "I think we should just have the option of Light/Dark") — on any given screen it looked identical to one of the other two with nothing saying which or why, so it read as a duplicate button. Anyone still carrying it is migrated below. 2. Every colour utility the templates use is remapped in the Tailwind config to a CSS variable (as an "R G B" triplet so /opacity modifiers keep working). Crucially the maps are PER PLUGIN — backgroundColor vs textColor etc. — so bg-white can go dark while text-white stays white, and text-navy flips light while bg-navy stays navy. 3. Both :root (light) and [data-theme="dark"] var blocks are emitted, so toggling the attribute restyles instantly. Tokens whose colour is identical in both modes are simply not mapped and fall through to stock Tailwind. Since 2026-08-31 the token maths lives in config/tailwind/tailwind.config.js and the CSS is BUILT at deploy (scripts/build/build_css.sh → /static/tw.css): the Play CDN was a compiler running in the browser on every navigation — real seconds on a phone. Local dev: run `bash scripts/build/build_css.sh` once (and after adding classes no template used before). #}
